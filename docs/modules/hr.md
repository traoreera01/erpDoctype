# Ressources humaines (`hr`)

Le dossier du personnel : employés et structure de l'organisation, recrutement, présences et shifts, congés, évaluations, formation, notes de frais et déplacements, jusqu'à la sortie de l'employé. Deuxième module du jeu par la taille (114 DocTypes).

## Points clés

- **`Employee`** (hébergé dans `setup` — la fiche générique) : identité, contrat, salaire, `employment_type`, service en `Department` (arborescent, `setup`) ; le plugin doit la relier à un compte utilisateur (`Member` du module `iam`) — voir le plugin `hr` d'exemple du dépôt moteur. Les DocTypes RH propres (congés, présences, évaluations…) sont ici.
- **Congés** : `Leave Type`, `Leave Allocation` (LEAL-), `Leave Application` (LEAP-, **workflow d'approbation**), `Leave Policy`, `Compensatory Leave Request`, `Leave Ledger Entry` (LLE-, le registre immuable des mouvements de solde — écrit par les hooks, fermé à l'écriture humaine).
- **Présence** : `Attendance` (ATTE-), `Employee Checkin`, `Shift Type`/`Shift Assignment` (SA-)/`Shift Request` (SR-), `Overtime Slip` (OS-).
- **Notes de frais** : `Expense Claim` (EC-, **workflow**) avec lignes `Expense Claim Detail` et taxes, avances `Employee Advance` (EA-).
- **Cycle de vie complet** : `Job Requisition` → `Job Opening` → `Job Applicant` → `Interview` → `Job Offer` → onboarding (`Employee Onboarding`) → évolutions (`Employee Promotion`, `Employee Transfer`) → sortie (`Employee Separation`, `Exit Interview`, `Full and Final Statement`).
- **Évaluations** : `Appraisal Cycle`, `Appraisal` (APPR-) avec KRA et objectifs (`Goal`, `KRA`), feedback à 360°.
- **`Employee Referral`** : permet de verser la prime à un employé ; `Payroll` la traite.

## Implémentation en plugin xcore

- Plugin `hr`, ordre P4 avec `payroll` ; le plugin `hr` de test du dépôt moteur (`tests/support/plugins/hr`) est le gabarit direct : YAML + un hook.
- **Hooks à écrire** : décompte des soldes de congés dans `Leave Ledger Entry` à la soumission/annulation d'une demande, dotation ou reprise (`Leave Allocation`), contrôle de chevauchement des congés, blocage de la paie sur un employé parti, écriture comptable de `Expense Claim`.
- `Employee` doit être relié au compte d'authentification : le modèle du moteur (hook sur le statut « Parti » qui désactive le compte) est à reprendre.
- Les deux workflows (`Expense Claim`, `Leave Application`) exigent les grants `hr:expense_claim:workflow_*` et `hr:leave_application:workflow_*` — déclarés par le service `doctype_grants` sans code supplémentaire.
